# faceted-search-go

面向文档集合的内存型分面检索引擎。文档由正文（`Title`/`Body`）与若干结构化
属性组成，查询同时返回匹配文档与各分面候选计数。写入（插入、删除、属性更新）
与查询可并发执行，一次响应中的结果集与全部分面计数始终来自同一个不可变快照。

## 快速开始

```go
engine := faceted.NewEngine([]faceted.FacetSpec{
    {Name: "color", Type: faceted.FacetFlat},
    {Name: "cat", Type: faceted.FacetHierarchical},
})

id, _ := engine.Put(&faceted.Document{
    Title: "red shirt",
    Attrs: map[string]string{"color": "red", "cat": "apparel/shirts"},
})

result := engine.Search(faceted.SearchParams{
    Query:   "shirt",
    Filters: map[string]faceted.Filter{
        "color": faceted.NewFilter("color", "red"),
    },
    Offset: 0,
    Limit:  20,
})

_ = id
_ = result.Total
_ = result.Documents
_ = result.Facets["color"].Buckets
_ = result.Facets["cat"].Tree
```

写入接口：

- `Put(doc)`：`ID == 0` 时分配递增 ID；给定已存在 ID 时整体替换该文档。
- `Update(id, attrs)`：只替换属性，标题与正文保持不变。
- `Delete(id)`：删除文档。

## 过滤语义

- 同一分面内多个选中值按 **或（OR）** 合并：`color = red|blue` 命中任一值。
- 不同分面之间按 **与（AND）** 组合：`color = red AND size = m`。
- 自由文本查询将 `Query` 按空白分词，所有 token 都需（大小写不敏感地）出现在
  标题或正文中；文本条件同样与分面过滤 AND 组合。
- 最终结果集等价于对每篇文档逐文档判定上述条件。

## 分面计数语义

所有分面（**包括**用户正在过滤的分面本身）都在“当前完整结果集”上计数：

- 计数与全部已选过滤条件联动。选中某值后，其余分面只统计仍满足全部条件的文档。
- 计数覆盖完整结果集，与分页窗口无关；翻页只改变 `Documents`，不改变计数。
- 一个文档对单个分面桶至多计一次。
- 未被任何当前结果文档命中的分面值不出现在响应中；被选中但当前计数为 0 的层级
  节点仍会以 `Count == 0`、`Selected == true` 出现在树中，便于导航控件呈现。

## 层级分面

层级分面的值是用 `/` 分隔的路径，例如 `electronics/phones/mobile`。

- **父级选中**：选中节点命中其自身与整棵子树（值等于该节点或以 `node/` 开头），
  子级计数是当前结果集中每个子节点的不同文档数；父节点计数是子树的去重汇总，
  一篇文档在一个桶内不会重复计数。
- **子级选中**：只有该节点自身及其后代命中；结果中仍展示其全部祖先节点，祖先的
  `Count` 是当前结果集向祖先汇总的去重文档数（因此子级选中时父级计数等于该子树
  在当前结果中的文档数），但只有用户显式选中的节点 `Selected == true`，祖先不会
  被隐式标记为选中。
- 同一层级分面选多个节点仍为 OR；与其他分面 AND。

## 快照一致性

- 索引内部保存一个不可变 `snapshot`。任何写入都基于当前快照复制出新快照（写时
  复制），在写锁内完成全部修改后原子替换指针，并令版本号 `version` 加一。
- 查询在读锁下只取一次快照指针，随后无锁读取；因此：
  - 不会观察到半更新的文档，也不会出现字段级的新旧混合；
  - 同一响应中的结果集与全部分面计数必然同属一个更新边界，不会出现“新计数 +
    旧结果”或“旧计数 + 新结果”；
  - 响应携带 `Version`，可用于判断两次响应之间是否发生过写入。

## 稳定分页

匹配文档按 `DocID` 升序返回。`ID == 0` 的插入会被分配严格递增的 ID，相同所有
可排序键的文档也有确定的先后顺序。过滤条件相同且无并发写入时，配合单调递增的
`Offset` 翻页不会重复或遗漏文档；发生写入后，新的响应属于新版本，调用方应使用
新的 `Total`/游标重新对齐页面。

## 计数缓存、失效与复杂度

- 分面计数按 `(version, facet, query tokens, 全部分面过滤)` 缓存。高频过滤组合
  第二次起直接命中；命中时的 `DocsScanned` 为 0。
- 任何 `Put`/`Update`/`Delete` 都会提升版本并清空整个计数缓存，因此不可能返回
  过期计数。
- 查询路径：先在有序倒排表上做集合运算得到匹配集（AND 用归并求交、同面值 OR 用
  归并求并），计数只遍历当前匹配集；无过滤时直接使用倒排表长度，不扫描任何文档。
  因此含计数的过滤查询工作量随“当前结果集大小 / 命中的分面值数量”增长，而不是
  随全库文档数线性增长（首次冷查询为 `O(|结果集| × 分面数)`，缓存命中为
  `O(分面值桶数)` 的结果组装）。
- 写入路径只增删该文档自身 token 与自身属性值对应的倒排表（层级值包含其祖先
  路径），更新开销与“被影响的分面值数量”相关，与全库文档数无关。

## 测试

```bash
go test -race ./...
```

测试覆盖：同面多值 OR、异面 AND、计数与逐文档判定一致、层级分面父子语义、
增量写入/删除/属性更新、并发读写快照一致性（race 检测）、计数缓存命中与写入
失效、以及稳定分页无重复无遗漏。
