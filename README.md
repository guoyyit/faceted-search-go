# faceted-search-go

面向文档集合的内存分面检索与过滤导航库。文档除正文外带有若干结构化属性，
查询同时返回当前页文档与各分面的候选计数；用户组合选择分面值即可逐步
缩小结果集，计数随过滤条件联动并始终与当前结果集一致。

支持：

- 多维分面：同一分面内多选按 **或(OR)** 合并，不同分面之间按 **与(AND)** 组合；
- 平铺分面与层级分面（父子树，带向下汇总）；
- 增量写入、删除、属性更新；
- 查询与写入并发，单次响应内结果集与全部分面计数来自同一个一致性快照；
- 稳定分页（默认按文档 ID 排序，或按正文排序并以 ID 作为确定性决胜键）；
- 高频过滤组合的计数缓存，写入触发 O(1) epoch 失效，热查询不随全库规模线性增长。

## 快速开始

```go
schema := faceted.NewSchema()
_ = schema.AddFlat("color")
_ = schema.AddFlat("size")
_ = schema.AddHierarchy("category")

ix := faceted.NewIndex(schema)
_ = ix.Upsert(faceted.Document{
    ID:   "doc-1",
    Body: "wireless headphone review",
    Attrs: faceted.Attributes{
        "color":    {faceted.FacetPath{"red"}},
        "size":     {faceted.FacetPath{"m"}},
        "category": {faceted.FacetPath{"electronics", "audio", "headphone"}},
    },
})

res, _ := ix.Search(faceted.Query{
    Filter: faceted.Filter{
        "color": {faceted.FacetPath{"red"}, faceted.FacetPath{"blue"}}, // 同面 OR
        "size":  {faceted.FacetPath{"m"}},                              // 跨面 AND
    },
    Offset:       0,
    Limit:        20,
})
// res.Total     —— 当前结果集总数（不受分页影响）
// res.IDs       —— 当前页文档 ID
// res.Facets    —— 各分面候选值与联动计数
```

`Search` **默认总是同时返回文档页、结果集总数与全部分面计数**，无需设置任何开关；
`Query.ReturnCounts` 字段已废弃并被忽略（保留是为了让既有调用方代码无需修改）。

一篇文档在同一分面上可以有多个值；多值文档在同面多选 OR 合并时只计一次。

## 过滤语义

- **同一分面内**：多个选中值取并集（OR）。一篇文档只要带有其中任一值即匹配。
- **不同分面之间**：各分面的匹配结果取交集（AND）。
- **层级分面**：选中某节点，匹配赋给该节点本身或其任意后代节点的文档
  （子值沿祖先链向上汇总，rollup）。
- 最终结果集等价于对每篇文档逐个判定属性（参考实现见 `matchFilter`）。

用集合表示：对分面 `f` 的选中值 `V_f`，

```
Results = ⋂_f ( ⋃_{v ∈ V_f} Postings(f, v) )
```

层级分面中 `Postings(f, v)` 是 `v` 子树的并集。

## 分面计数语义（联动计数）

### 基本规则：全部基于当前完整结果集

**所有分面**（包括当前带有选中值的分面自身）的候选计数都基于“满足当前完整过滤
条件”的同一个结果集统计，与逐文档判定属性的口径一致，与分页窗口无关。
`Offset/Limit` 只影响返回页，不影响 `Total` 与任何计数。

- 平铺分面上，候选值 `v` 的计数 = 当前结果集中包含 `v` 的文档数；同一篇文档在该
  候选值上只计一次（文档多值时，它可以同时计入多个候选值）。
- 因此选中 `color=red` 后，`color` 分面只返回 `red`（计数等于结果集总数）；`blue`、
  `green` 等当前结果集内为 0 的未选值不再出现。该分面的计数口径与其它分面完全
  一致，任何候选计数都不会超过结果集总数。
- 当结果集中每篇文档都恰好对某平铺分面赋有一个值时，该分面全部候选计数之和
  恰好等于结果集总数。
- 层级节点的计数是**子树合计**：当前结果集中赋给该节点本身或其任意后代节点的
  文档数量（去重）。
- 计数为 0 且未选中的候选值不出现在响应中；被选中但当前计数为 0 的值仍然返回，
  并标记 `Active=true`，用于展示已失效的选择。

一次响应中的页、`Total` 与全部分面计数由同一份结果集计数向量生成，三者必然
一致（见“一致性与并发”）。

### 层级分面的父子呈现规则

层级计数同样全部基于当前完整结果集；倒排表中祖先节点本身就是其全部后代的
rollup 并集，因此“结果集 ∩ 子树”的交集大小自然给出下面的呈现效果：

1. **父级选中**：选中父节点即选中整个子树；父节点计数等于当前结果集总数，
   各子节点按各自子树在当前结果集内的文档数显示，这些子值共同切分父级子树。
   不满足其它过滤条件的子分支计数为 0，默认隐藏。同时选中父与后代时按 OR
   合并，因后代子树包含在父子树内，父级自动占优，结果等同只选父。
2. **子级选中**：沿选中路径的祖先节点仍然显示，但计数只包含落在所选子树内的
   文档（选中一个叶子时，父级显示的就是所选子树合计，绝不会显示未过滤前的整棵
   祖先汇总）。所选子树之外的兄弟分支、与选择路径无关的其它树分支计数为 0，
   默认隐藏；被选中的节点本身即使计数为 0 也返回并带 `Active=true`。
3. **同面多选**：选中多个子树时按 OR 合并结果集；各节点仍按“结果集 ∩ 自身子树”
   计数，两个不相交子树可同时显示。

## 一致性与并发

- 索引内部用一把 `sync.RWMutex` 保护所有可变状态（文档表、倒排表、有序树）。
- 一次 `Search` 在**整个响应构建期间持有读锁**，因此页内文档、`Total` 与每个分面
  计数必然来自同一个更新边界：不会出现“新计数 + 旧结果”或“旧计数 + 新结果”。
- `Upsert` / `Delete` / `UpdateAttributes` 持写锁一次性完成全部字段与倒排项更新，
  读方不可能观察到半更新的文档或字段级混合状态。
- 计数缓存有独立的互斥锁保护其内部 map；锁的获取顺序始终为“索引锁 → 缓存锁”，
  不会死锁。

## 稳定分页

- 默认 `SortByID`：按文档 ID 升序，底层用随机平衡二叉搜索树（treap）保存有序 ID，
  翻页为有序遍历，顺序完全确定。
- `SortByBody`：先按正文升序，正文相同时以文档 ID 升序决胜。
- 在过滤条件相同且没有并发写入时，连续翻页不会重复或遗漏；排序键相同时的先后
  顺序由决胜键确定。

注意：并发写入会改变结果集本身，这是预期行为；快照隔离保证的是**单次响应**内部
的一致性，而不是跨响应的游标稳定性。

## 计数缓存与复杂度

每个分面节点维护两套倒排结构：

- 哈希集合：O(1) 成员判定与计数；
- 有序 treap：单值过滤时直接作为分页顺序源，无需对全库排序。

缓存两类对象，键为过滤条件的规范化字符串（分面名与值均排序，顺序无关）：

- 过滤结果集（用于 `Total` 与分页）；
- 该过滤条件对应完整结果集上的分面计数向量（每个分面每个节点的计数）。
  空过滤（默认查询）同样缓存，因此默认响应的计数也是热路径。

一次查询只生成并缓存**一份**结果集与计数向量，页、总数与全部分面计数都从它
派生，天然共享同一个更新边界。

任何成功的 `Upsert` / `Delete` / `UpdateAttributes` 都把缓存 epoch 加一，
逻辑失效全部条目（O(1)），读取时惰性丢弃过期条目，因此**不可能返回过期计数**。

复杂度（`V` = 查询涉及的分面节点数/选中值数量，`R` = 当前结果集大小）：

- 热的含计数查询：计数来自缓存，开销与分面值数量相关，**不随文档总量线性增长**；
  选择性单值过滤的分页直接走有序倒排树。基准测试 `BenchmarkSelectiveWarmQuery_
  10k/100k` 与 `BenchmarkDefaultWarmQuery_10k/100k` 中，1 万与 10 万文档的热查询
  延迟基本相同。运行 `go test -bench=. ./...` 可复现该对比。
- 冷查询：按最小集合优先的方式做交集，代价随命中规模而非全库规模；结果与计数
  向量随后被缓存。
- 写入：更新的倒排节点数与该文档拥有的分面值（层级值含其祖先链）数量相关，
  与全库文档数无关；缓存失效本身为 O(1)。

## API 概览

| 类型/方法 | 说明 |
| --- | --- |
| `NewSchema` / `(*Schema).AddFlat` / `AddHierarchy` | 定义分面 |
| `NewIndex(schema)` | 创建并发安全索引 |
| `(*Index).Upsert(Document)` | 插入或整体替换文档 |
| `(*Index).Delete(DocID)` | 删除文档 |
| `(*Index).UpdateAttributes(DocID, Attributes)` | 仅替换属性，正文不变 |
| `(*Index).Get(DocID)` / `Len()` | 读取 |
| `(*Index).Search(Query)` | 一致性快照查询：页 + 总数 + 分面计数 |

`Search` 会深拷贝传入的 `Filter`，调用方在查询后修改原过滤条件不影响索引。
`Upsert`/`UpdateAttributes` 也会深拷贝传入文档与属性，调用方可安全复用原对象。

## 测试

```sh
go build ./...                       # 构建
go vet ./...                         # 静态检查
go test -count=1 ./...               # 功能测试（禁用缓存）
go test -race ./...                  # 并发读写竞争检测
go test -bench=. ./...               # 热查询不随全库规模线性增长的基准
```

测试覆盖：

- 被选中分面自身的计数与结果集总数一致（不超过总数；单值平铺分面候选计数之和
  等于总数），且不随分页窗口变化；
- 默认查询（不设置任何开关）同时返回页、总数与全部分面计数；
- 同面多选 OR / 跨面 AND 及与逐文档判定的等价性；
- 多值文档在单个候选值上去重，同一文档可同时计入多个候选值；
- 层级 rollup、父级选中/子级选中/同面多子树选择的父子计数呈现，以及计数为 0 的
  已选值仍返回并标记 `Active`；
- 缓存失效（插入/属性更新/删除后不返回旧值，含空过滤向量）与热查询结构性验证；
- 并发读写下对**每一次响应的全部分面**（含被选中分面）在同一次读锁快照内做精确
  回放校验（`TestConcurrentReadersAndWriters`，循环有界，自行结束），并通过
  `-race`；
- 非法过滤（未知分面、空路径、平铺多段路径）、负数分页参数被明确拒绝，且单个
  非法请求不影响后续请求；
- 稳定分页与正文排序决胜键。
